# v0.3.0 Plan: JSON-first, pysnmp frozen

## Decision

Drop active pysnmp development. tsmi is an ASN.1 → portable JSON schema compiler,
independent of the pysnmp ecosystem. Keep the pysnmp formatter but freeze it — no
new features, no gap-chasing pysmi. Document it as best-effort.

pysmi remains a correctness benchmark (OID values, nodetypes, member counts) — not a
target to imitate.

### 2. JSON gap J-G1: add `class` field to every object in JSON output
Source: `trishul_smi/output/json_fmt.py` → `_obj_dict()`

pysmi emits `"class": "objecttype"` (lowercase, no hyphen) on every object entry.
tsmi uses `object_type: "OBJECT-TYPE"` (original SMI casing).

Add a derived `"class"` field alongside `object_type` in `_obj_dict()`.
Mapping (SMI keyword → class string):
```
MODULE-IDENTITY      → moduleidentity
OBJECT-IDENTITY      → objectidentity
OBJECT-TYPE          → objecttype
NOTIFICATION-TYPE    → notificationtype
OBJECT IDENTIFIER    → objectidentifier
OBJECT-GROUP         → objectgroup
NOTIFICATION-GROUP   → notificationgroup
MODULE-COMPLIANCE    → modulecompliance
AGENT-CAPABILITIES   → agentcapabilities
TRAP-TYPE            → traptype
```
Also add `"class"` to the `types` section (TC entries): always `"textualconvention"`.

File: `json_fmt.py` — `_obj_dict()` and `_type_dict()`.
Test: existing tests check `object_type`; add assertions for `class` field.

### 3. JSON gap J-G2: capture MODULE-COMPLIANCE group/object refs
Source: `trishul_smi/parser/transformer.py` → MODULE-COMPLIANCE handling

pysmi emits `"modulecompliance": [{module, object}, ...]` on MODULE-COMPLIANCE objects —
the list of OBJECT-GROUPs and NOTIFICATION-GROUPs that the compliance statement
references (the `GROUP` and `MANDATORY-GROUPS` clauses).

Currently tsmi parses MODULE-COMPLIANCE but `members` is null on those objects.

Steps:
a. In `transformer.py`, extract GROUP/MANDATORY-GROUPS clause members and store them
   in `MibObject.members` for MODULE-COMPLIANCE objects (same list[str] field already
   used for OBJECT-GROUP and NOTIFICATION-GROUP).
b. In `json_fmt.py` `_obj_dict()`, emit them as `members` with `{module, object}` dicts,
   same as groups and notifications already do.

Files: `transformer.py`, `json_fmt.py`.
Test: compile a MIB with MODULE-COMPLIANCE (e.g. IF-MIB ifCompliance) and assert
      members list is present and non-empty.

### 4. JSON gap J-G3: keep module_metadata in no-texts mode (structural only)
Source: `json_fmt.py` → `format()`

In nt mode tsmi drops the entire `module_metadata` block. pysmi keeps `lastupdated`
and `revisions` (stripped of description text). These are structural/temporal metadata
that consumers need for OID-tree provenance, not "text".

Change: always emit `module_metadata` with `lastupdated` and `revisions` (date only,
no description). Only `organization`, `contactinfo`, and `description` are suppressed
in nt mode.

File: `json_fmt.py` → `format()`.
Test: compile with `no_texts=True` and assert `module_metadata` is present with
      `lastupdated` and `revisions[].date`, but no `description`/`organization`/
      `contactinfo`.
