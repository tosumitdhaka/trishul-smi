# v0.4.7 Plan — Real-World MIB Correctness

**Theme:** compile the MIBs users actually have. All parser-level correctness fixes from the
independent code review, plus the long-standing SMIv1 TRAP-TYPE data-loss bug.

**Status:** shipped 2026-09-22

## Issues in scope

| Issue | Title | Notes |
|-------|-------|-------|
| #11 | `_strip_macro_bodies` not comment/quote-aware | Make the stripper token-aware (skip `QUOTED_STRING` and comment regions before matching `\bMACRO\b`), mirroring `_normalize_wrapped_comments`. Covers both the commented-out-macro case and the DESCRIPTION-string case (see review comment on #11). |
| #13 | SMIv1 TRAP-TYPE loses ENTERPRISE, full OID, DESCRIPTION | Transformer must preserve ENTERPRISE and DESCRIPTION; resolve full OID through the enterprise chain. |
| #21 | Declared vs requested module-name mismatch | Re-key by declared name + alias record, or warn + alias-aware dependency discovery. Fixes phantom fetches, wrong `is_dependency`, cache misses. |
| #24 (part) | `_detect_dialect` scans full text incl. comments | Unify with the transformer's imports-only heuristic — one dialect decision, not two. (Remaining #24 items are v0.4.10.) |

## Non-goals

- Any HTTP/reader behavior (v0.4.8).
- Concurrency/async changes (v0.4.9).
- Output format changes (v0.4.10).

## Acceptance criteria

- New tests: MACRO in DESCRIPTION string, MACRO in comment, real macro block coexisting
  with both; TRAP-TYPE fields present in JSON output; misnamed-file module resolves
  dependents, names results consistently, and hits cache on second run; SMIv1 module with
  "SNMPv2-SMI" in a comment parses as SMIv1.
- No regression in local corpus compile counts (release gate step 2 per
  `docs/release-checklist.md`).
- All 412+ existing tests pass; coverage stays ≥95%.
