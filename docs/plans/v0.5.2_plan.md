# v0.5.2 Plan — Lint Auto-Remediation + JSON IR Enrichment

**Theme:** Turn the linter into an active corpus-curation tool (`tsmi lint --fix`, #31),
fix its one known false positive (#34), and enrich the module JSON IR with the
value-level data consumers need to render SNMP values (#35 — enums, UNITS,
constraints; additive fields, `schema_version` stays 1.1). Schedules all three
currently-open issues in one release.

**Status:** shipped 2026-09-28

## In scope — lint (GitHub #31, #34)

| # | Item | Notes |
|---|------|-------|
| 1 | **`tsmi lint --fix`** | Applies mechanical fixes to source MIB files for fixable findings. V1 fixable set: `missing-import` (type-role only — add the missing `FROM` import when the symbol resolves to exactly one provider module in the closure; ambiguous or unresolvable symbols are reported, not fixed) and `unused-import` (remove the unused symbol from the IMPORTS clause; remove the clause entirely when it empties). Member/OID-role `missing-import` findings are NOT fixable (they are legal unimported OID references, not defects). |
| 2 | **`--diff` dry-run mode** | `tsmi lint --fix --diff` prints unified diffs of what would change and writes nothing. Default `--fix` (without `--diff`) writes files atomically (temp-file rename, same convention as MibCache). |
| 3 | **Report shape** | Text and JSON outputs grow a `fixed` section: which findings were fixed, which were left (with reason). Exit codes: 0 = nothing to fix / all fixed cleanly; 1 = unfixed findings remain; 2 = usage errors. |
| 4 | **`missing-description` scoping fix** | Module-level check fires only on object-bearing modules. TC-only modules without MODULE-IDENTITY (`SNMPv2-TC`, `SNMPv2-CONF`, `IPV6-TC`) are legal and no longer flagged. 9/9 corpus firings were module-level; 3 were IETF standard modules. Warning-severity today, so `--fail-level error` CI gates are unaffected either way. |

## In scope — JSON IR enrichment (GitHub #35)

| # | Item | Notes |
|---|------|-------|
| 5 | **Object-level `enums`** | Ordered label→number mappings for INTEGER/BITS inline constraints (e.g. `ifOperStatus` → `{"up": 1, "down": 2, ...}`); BITS likewise. Data already lives in `MibObject.constraints` — this is emission only. |
| 6 | **Object-level `units`** | The UNITS clause (parsed at `parser/grammar/smiv2.lark:102` but dropped at transform time today) is threaded through the transformer into the model and emitted (e.g. `ifSpeed` → `"bits/second"`). The only new parsing plumbing in this release. |
| 7 | **Object-level `constraints`** | Numeric ranges and size limits, when present (e.g. `ifMtu`). Same `constraints` source as enums. |
| 8 | **Schema policy, docs, contracts** | All new fields are additive and optional — older consumers must treat them as absent-able. `schema_version` stays `1.1` per the bundle compatibility policy (bump only on breaking IR changes). Contract tests pin the new fields; `--reproducible` output stays deterministic; `docs/json-bundles.md` documents the new fields. |

## Safety rules for `--fix` (hard requirements)

- Only the two fixable check kinds above ever modify a file; every other finding is
  report-only.
- Idempotency: a second `--fix` run must be a no-op (pinned by test).
- Line endings and trailing whitespace of untouched lines are preserved byte-for-byte
  (the fixer edits only the IMPORTS block; pinned by test).
- A fix that would leave the file unparseable is detected (re-parse after edit) and
  rolled back with an error.
- No fix is attempted on modules fetched over HTTP or from ZIP sources — local
  `--mib-dir` files only (matching the corpus-curation use case; out-of-scope
  sources are report-only).

## Non-goals

- Fixes for `undefined-type`, `unresolvable-oid`, `duplicate-oid-arc`,
  `missing-status`, `missing-description`, member-role `missing-import`.
- Watch-mode or compile integration (lint --fix is a one-shot command).
- Any change to lint detection semantics — only remediation is added (item 4 is a
  scoping correction of an existing check, not a new one).
- tsnmp-side rendering (enum labels in CLI output, normalized JSON) — consumer
  follow-up tracked on the trishul-snmp roadmap, pending this IR.
- Any breaking IR change or `schema_version` bump.
- Watch-mode known limits (recompile of dependents when a missing dependency is
  adopted; removal beyond notice-only) — still deferred.

## Acceptance criteria

- `--fix --diff` on the 12-defect corpus fixture set produces exactly the expected
  diffs and writes nothing (test with tmp_path fixtures reproducing the Juniper
  `DisplayString` shape).
- `--fix` writes the corrected files; a re-lint reports zero fixable findings.
- Idempotency, byte-preservation of untouched lines, rollback-on-unparseable, and
  HTTP/ZIP source refusal each pinned by a dedicated test.
- Re-lint of the 412-module corpus reports zero module-level `missing-description`
  findings on TC-only modules (`SNMPv2-TC`, `SNMPv2-CONF`, `IPV6-TC`); genuine
  module-level findings on object-bearing modules still fire.
- A compiled IF-MIB carries `enums` for `ifOperStatus`. The local corpus IF-MIB
  variant has no UNITS clause and no `ifMtu` range, so `units` and range
  `constraints` are verified on DISMAN-PING-MIB `pingCtlDataSize` (`units` =
  `"octets"`, range `0..65507`); shapes for all three fields are additionally
  pinned by contract tests.
- Older consumers (tsnmp 0.5.0) load the new JSON unchanged (fields ignored until
  the tsnmp-side rendering work lands).
- `schema_version` remains `1.1`; contract tests updated.
- `tsmi convert` round-trip unaffected.
- Docs: `docs/cli.md` lint section gains the `--fix` / `--diff` semantics + safety
  rules; `docs/json-bundles.md` gains the new object-level fields.
- Release gate + corpus compile per `docs/release-checklist.md` (412 ✅).
