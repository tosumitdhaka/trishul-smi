# v0.5.2 Plan — Lint Auto-Remediation

**Theme:** `tsmi lint --fix` — mechanical, safe auto-remediation of lint findings,
turning the linter into an active corpus-curation tool (the natural next step after
the first corpus run found 12 genuine vendor defects).

**Status:** planned

## In scope

| # | Item | Notes |
|---|------|-------|
| 1 | **`tsmi lint --fix`** | Applies mechanical fixes to source MIB files for fixable findings. V1 fixable set: `missing-import` (type-role only — add the missing `FROM` import when the symbol resolves to exactly one provider module in the closure; ambiguous or unresolvable symbols are reported, not fixed) and `unused-import` (remove the unused symbol from the IMPORTS clause; remove the clause entirely when it empties). Member/OID-role `missing-import` findings are NOT fixable (they are legal unimported OID references, not defects). |
| 2 | **`--diff` dry-run mode** | `tsmi lint --fix --diff` prints unified diffs of what would change and writes nothing. Default `--fix` (without `--diff`) writes files atomically (temp-file rename, same convention as MibCache). |
| 3 | **Report shape** | Text and JSON outputs grow a `fixed` section: which findings were fixed, which were left (with reason). Exit codes: 0 = nothing to fix / all fixed cleanly; 1 = unfixed findings remain; 2 = usage errors. |

## Safety rules (hard requirements)

- Only the two fixable check kinds above ever modify a file; every other finding is
  report-only.
- Idempotency: a second `--fix` run must be a no-op (pinned by test).
- Line endings and trailing whitespace of untouched lines are preserved byte-for-byte
  (the fixer edits only the IMPORTS block; pinned by test).
- A fix that would leave the file unparseable is detected (re-parse after edit) and
  rolled back with an error.
- No fix is attempted on modules fetched over HTTP or from ZIP sources — local
  `--mib-dir` files only (matching the corpus-curation use case; out-of-scope
  sources are report-only).

## Non-goals

- Fixes for `undefined-type`, `unresolvable-oid`, `duplicate-oid-arc`,
  `missing-status`, `missing-description`, member-role `missing-import`.
- Watch-mode or compile integration (lint --fix is a one-shot command).
- Any change to lint detection semantics — only remediation is added.

## Acceptance criteria

- `--fix --diff` on the 12-defect corpus fixture set produces exactly the expected
  diffs and writes nothing (test with tmp_path fixtures reproducing the Juniper
  `DisplayString` shape).
- `--fix` writes the corrected files; a re-lint reports zero fixable findings.
- Idempotency, byte-preservation of untouched lines, rollback-on-unparseable, and
  HTTP/ZIP source refusal each pinned by a dedicated test.
- Docs: `docs/cli.md` lint section gains the `--fix` / `--diff` semantics + safety
  rules.
- Release gate + corpus compile per `docs/release-checklist.md` (412 ✅).

## Suggested lanes

Single feature, single lane (lint engine + CLI + tests + docs). Independent review
before tag per standing practice.
