# v0.4.8 Plan — Fetch-Layer Limits & Input Hardening

**Theme:** make `max_mib_size` actually bound memory, and harden the input boundary. The
review's recurring "limits enforced at the wrong layer" theme: guards exist but are
bypassable by exactly the inputs they were built for.

**Status:** planned

## Issues in scope

| Issue | Title | Notes |
|-------|-------|-------|
| #17 | ZipReader nested-archive reads bypass `max_mib_size` | Bounded read (`fh.read(max_size + 1)`) + `MibSizeLimitError` on overrun for nested archives; optional total-bytes cap per fetch. |
| #18 | HttpReader: size checked after buffering; HEAD 404 misreported; dead ETag machinery | Streaming GET with early abort; drop the HEAD pre-check; GET is authoritative for not-found (preserve #4 semantics from v0.3.1: transport failure ≠ missing); persist ETags or delete the 304 path (YAGNI decision); guard malformed Content-Length. |
| #22 | Validate MIB names at CLI/config boundary | `^[A-Za-z][A-Za-z0-9-]*$` with actionable error. |
| #23 (item 2) | `--online` help text names wrong sources | Correct to `mibs.pysnmp.com` + `mibbrowser.online` (`config.py:20-24`). |

## Non-goals

- Parser changes (v0.4.7); concurrency/cache (v0.4.9); output (v0.4.10).

## Acceptance criteria

- Oversized nested zip → `MibSizeLimitError`, not OOM (test).
- Chunked / no-Content-Length oversized response → `MibSizeLimitError` without full-body
  buffering (test).
- HEAD 404 / 405 but GET 200 → module compiles (test with pytest-httpx scripted
  asymmetric responses).
- Malformed Content-Length → not misreported as network error (test).
- Hostile MIB names rejected at CLI parse time (test).
- Release gate per `docs/release-checklist.md`.
