# v0.5.0 Plan — Breaking Cleanup & Workflow Features

**Theme:** the first minor bump (reserved for breaking scope, per the versioning
convention): deliver the pysnmp `.py` removal promised by the v0.4.10 deprecation,
close the last known correctness edge case, and ship the two highest-value workflow
features (lint mode, watch mode) plus the plugin escape hatch that makes the removal
safe for anyone who still needs a custom format.

**Status:** planned

## In scope

| # | Item | Notes |
|---|------|-------|
| 1 | **pysnmp `.py` format removal** (breaking; follow-up to #24 deprecation) | Delete `PysnmpFormatter`, the `-f pysnmp` option, the v0.4.10 deprecation-notice paths, and `tests/test_pysnmp_deprecation.py`; sweep legacy pysnmp-output tests (the `filterwarnings` mark in `test_compiler.py` dies with them). `tsmi convert` (reading existing `.py` files via `convert/pysnmp_reader.py`) is UNAFFECTED — keep its tests. The in-code TODOs at `pysnmp_fmt.py:282,293` die with the file. `-f pysnmp` must error with an actionable "removed in v0.5.0 — use the JSON bundle output" message. Docs: drop the pysnmp sections from `docs/cli.md`, `docs/python-api.md`, `docs/architecture.md` (package layout + format lists). CHANGELOG leads with the breaking change. Python-API removal: the `PysnmpFormatter` import path disappears. |
| 2 | **Offline-fallback staleness fix** (v0.4.10 review M1) | When the resolver's fetch-result skip guard discards a successfully-fetched module whose declared name was already claimed — and the claiming entry was served by the offline cache fallback — prefer the fresh fetch: re-record through `_record_module` (which emits the collision warning) instead of keeping the fallback-served stale entry. Narrow, currently disclosed by three warnings; this makes the fresh source win. Test: the review's exact reproduction (cached misnamed alias, `LAST-UPDATED 2000`; genuine source now fetchable with `LAST-UPDATED 2003` → 2003 wins, collision warning present). |
| 3 | **`tsmi lint` — MIB validation mode** | New CLI command: `tsmi lint NAME... [--mib-dir ...] [--online] [--format text\|json]`. Single bounded check set (v1): missing imports (symbol referenced but never imported and not defined in-module); undefined types (SYNTAX/import with no TC or base type anywhere in the closure); unresolvable OIDs (parent chain dead-ends — reuse the `resolve_oids` pass); unused imports; duplicate OID arcs under the same parent. Findings grouped by severity (error/warning); JSON output for CI; exit 0 clean / 1 findings / 2 usage. Implementation note: runs the existing resolve pipeline and inspects the closure — no new parse path, no grammar changes. |
| 4 | **Watch mode** | `tsmi compile --watch` (requires explicit names or `--mib-dir`). Debounced (~300 ms) mtime polling of the source dirs — **no new runtime dependency** (watchfiles et al. rejected to keep the dep tree as-is). On change: recompile only the changed module and its transitive dependents (the topological dependency graph defines the invalidation set; the fingerprinted cache already makes re-parse precise). Same per-module results table per cycle; Ctrl-C exits cleanly with a summary. |
| 5 | **Plugin system for custom formatters** | Entry-point group `trishul_smi.formatters`: third-party packages expose a class conforming to the existing structural `FormatterProtocol`. `-f name` resolution: built-ins first, then discovered entry points; unknown name errors with the list of available formats (built-in + discovered plugins). Per-run formatter instances (v0.4.10) already make third-party formatters race-free. Tests via a registration/importlib-metadata hook (no real installation needed). Docs: "Plugins" section in `docs/architecture.md` with a minimal example. This is the pysnmp removal's escape hatch — anyone needing the old format can ship it as a plugin. |

## Non-goals

- **MIB borrowing** — rejected and dropped from the backlog (2026-09-22): its value
  (long-tail availability, CI speed, air-gapped closure) is already covered by the
  curated local corpus, the fingerprinted compiled cache, the v0.4.10 offline
  fallback, and the HTTP sources; and it would reintroduce a trust problem the 0.4.x
  program closed — a borrowed compiled artifact cannot be fingerprinted against a
  source you don't have, and a silently wrong artifact is worse than a fetch failure.
  If ever needed, the ReaderChain slot makes it a natural third-party package.
- FileReader/HttpReader fingerprint divergence for non-UTF-8 bytes (ultra-edge; on
  record in the v0.4.10 Known Limitations).
- TCPIPX-MIB support (still deferred from the original backlog).
- Performance work, grammar rewrites, new output formats in-tree.

## Acceptance criteria

- `-f pysnmp` errors with the actionable removal message; `tsmi convert` on an
  existing `.py` file still works; no pysnmp formatter code or tests remain; docs
  carry no pysnmp-output references (convert references stay).
- The v0.4.10-review M1 reproduction ends with the fresh source winning and a
  collision warning.
- `tsmi lint` reports each of the five check classes on minimal fixture MIBs (one
  test per check), exits 0 on a clean module, and emits valid JSON findings.
- `tsmi compile --watch` recompiles only the changed module + dependents (pinned via
  parse-count assertions), debounced, exits cleanly on Ctrl-C; no new runtime
  dependencies in `pyproject.toml`.
- `-f <plugin>` resolves a formatter registered via the entry-point hook; unknown
  `-f` lists built-in and discovered formats.
- Version 0.5.0; CHANGELOG leads with the breaking change; release gate + full
  corpus compile (412 ✅) per `docs/release-checklist.md`.
- Independent review of the diff before tagging (standing practice).
