# v0.5.1 Plan — Lint & Watch Ergonomics

**Theme:** polish the v0.5.0 features based on first real usage: the ergonomics
gaps hit during the corpus calibration, CI gating for lint, and the completion of
watch-mode's new-file story.

**Status:** shipped 2026-09-24

## In scope

| # | Item | Notes |
|---|------|-------|
| 1 | **`tsmi lint` no-name mode** | When only `--mib-dir` flags are given (no `NAME...`), lint the whole discovery set — mirroring compile's no-name compile-all. Evidence: the v0.5.0 corpus calibration had to extract 412 file stems from the output dir just to invoke lint. Same discovery semantics as compile (stem dedup, first `--mib-dir` wins). Exit codes unchanged. |
| 2 | **`--fail-level {error,all}` on lint** | CI gating: `all` (default, current behavior — any finding exits 1) vs `error` (only error-severity findings exit 1; warnings report but exit 0 when error-free). Affects exit code only — the JSON contract (`findings`/`summary`/`resolve_errors`) must stay byte-stable. Motivation: the 412-module corpus carries 650 unused-import warnings; without an errors-only mode, lint cannot gate CI on real corpora. |
| 3 | **`tsmi compile --list-formats`** | Prints the available output formats — built-ins first, then discovered `trishul_smi.formatters` plugins (via `output/registry.available_formats()`) — and exits 0. No MIB names required. Today the only way to see the format list is to trigger an unknown-format error. |
| 4 | **Watch mode: auto-adopt new files** | A new file appearing in `--mib-dir` mid-watch is currently only announced with a one-line notice (v1 limitation). Adopt it: add to the watch set, run an initial compile for it, announce the compile result. Removing files from the watched set stays notice-only (deletion handling is a separate design question). |
| 5 | **Two additive lint checks** | `missing-status` and `missing-description` (warning severity — omission is common in older vendor MIBs and does not break compilation; rationale in the module docstring, same as the v1 set). Check ids are additive; the JSON contract grows by new check-id values only, which is not a breaking change for the documented stable shape. |
| 6 | **Unblock plugin-provided `pysnmp` on the config/CLI path** | Found while verifying the new `trishul-smi-pysnmp` plugin (trishul-smi-plugins monorepo) against the released v0.5.0: `CompilerConfig.__post_init__` hard-rejected `"pysnmp" in formats` before the formatter registry was consulted, making the documented plugin escape hatch unreachable via CLI. Fix (implemented in the v0.5.1 working tree): config accepts the name like any plugin format; the removal guidance (removed in v0.5.0, JSON bundle output, `tsmi convert` unaffected, `trishul-smi-pysnmp` pointer) moved to `output/registry.py`'s resolution failure path; CLI exit 2 preserved. |
| 7 | **Python 3.13 CI fix + release-process amendment** | The `CI` workflow on `main` failed on every push since v0.4.9 (v0.4.9, v0.4.10 ×2, v0.5.0) on the 3.13 matrix leg only: `test_stat_failure_in_ttl_check_treated_as_stale`'s `_flaky_stat` shim rejected the `follow_symlinks` kwarg that `pathlib.Path.stat()` callers pass on Python 3.13. Invisible to every gate because the local gate and the release workflow run a single Python version (3.12) and the checklist never checked the CI-on-main run. Fix (implemented in the v0.5.1 working tree): shim forwards `**kwargs` to the real stat; `docs/release-checklist.md` now requires verifying ALL workflows green on the pushed commit, with this exact gap recorded as the rationale. |

## Non-goals

- `tsmi lint --fix` (auto-remediation) — deliberately deferred to **v0.5.2** (it
  writes to source files, a new class of behavior that deserves its own release and
  review).
- Watch-mode HTTP-source watching; file-removal handling; any changes to the v1
  check severities (member-role downgrade shipped in v0.5.0 stays as-is).
- TCPIPX-MIB, fingerprint divergence for non-UTF-8 bytes, plugin registry — parked
  with rationale in the roadmap Backlog note / v0.4.10 Known Limitations.

## Acceptance criteria

- `tsmi lint -d <dirs>` (no names) lints the discovery set; `--mib-dir` + names
  still works unchanged (test).
- `--fail-level error` exits 0 on warnings-only, 1 on any error; default `all`
  preserves current exit behavior (tests for both).
- `tsmi compile --list-formats` prints built-ins + discovered plugins (test with a
  mocked entry point) and exits 0 without MIB names.
- A new file added to `--mib-dir` mid-watch is compiled and watched from the next
  cycle (test: write fixture mid-run, assert its output appears).
- `missing-status` / `missing-description` each fire on minimal fixtures and stay
  silent on a compliant module (one test per check).
- Docs updated: `docs/cli.md` (lint no-name + `--fail-level`, compile
  `--list-formats`, watch semantics, check-set table grows two rows).
- Release gate + corpus compile per `docs/release-checklist.md` (412 ✅).
