# v0.5.3 Plan — Close Open Issues and Harden Existing Workflows

**Status:** shipped 2026-09-29. This is a patch release. Keep the JSON `schema_version` at 1.1
and keep the existing CLI commands. Follow `docs/release-checklist.md` for the release.

## Decision: keep `tsmi convert`

The PySNMP formatter plugin produces `.py` files; `tsmi convert FILE.py` reads old
`.py` files and emits JSON. The plugin does not replace reverse conversion. Keep
the command and fix its output-path validation (C1 below).

## Decisions from plan review

- **Watch exit contract (#40):** the exit code reflects state at stop, not
  history. Exit 1 only if a module is still failed, missing, or stale; a
  successful recovery clears the state. Document in `docs/cli.md`.
- **Lint fix comment policy (#36):** when removing a sole-line import clause,
  retain its trailing comment as a standalone comment. Conservative default
  that matches the fixer's byte-preservation safety rules.

## 2. Lint — #37, #36

1. In `trishul_smi/lint.py`, count an imported `TEXTUAL-CONVENTION` macro as
   used when the module defines a TC. Keep plain type assignments distinct.
   Also count macro-definition body symbol uses: `SNMPv2-CONF` imports
   `ObjectName`, `NotificationName`, `ObjectSyntax` from `SNMPv2-SMI` and uses
   them only inside its `MODULE-COMPLIANCE`/`AGENT-CAPABILITIES` macro bodies,
   so a TC-only fix leaves 3 of the 4 reproduced corpus firings standing
   (verified at plan review: `IPV6-TC` fires 1 `unused-import` on
   `TEXTUAL-CONVENTION`; `SNMPv2-CONF` fires 3 on those symbols). The
   preprocessor in `trishul_smi/parser/smi_parser.py` already locates
   macro-body spans to strip them; harvest identifier tokens from those spans
   onto the model and count them as uses in `_iter_references`, restricted to
   symbols already in the module's import map so unrelated tokens cannot mask
   a genuinely unused import. Keep emitted JSON unchanged (`schema_version`
   1.1) and test the cache round-trip (`tests/test_parser.py`,
   `tests/test_cache_fingerprint.py`, `tests/test_lint.py`). Test TC-only
   modules and macro-defining modules, and compare corpus finding-count
   changes to the v0.5.2 baseline: the expected end state is zero
   `unused-import` on `IPV6-TC` and `SNMPv2-CONF`. This completes #37.
2. Before `lint --fix` edits a local file, compare its decoded source fingerprint
   with the fingerprint of the source that produced the resolved module. Record
   the latter in `ResolveResult`; refuse fixes for offline-cache fallback or
   mismatches. A caller-supplied reader with a same-named, different local file
   must leave that file untouched. Test in `tests/test_lint.py` (#36).
3. Catch `_apply_edits` overlap failures per module, mark its findings `left`,
   and continue fixing other modules. When deleting a sole-line import clause,
   retain its trailing comment as a standalone comment. Test both behaviors
   and document the comment rule in `docs/cli.md` (#36).
4. Follow-on from #41 (added at implementation): with import-free root modules
   now correctly labelled SMIv2, the module-level `missing-description` check
   fired on `SNMPv2-SMI` (verified false positive: its 16 objects are all bare
   `OBJECT IDENTIFIER` assignments; it contains `MODULE-IDENTITY` only as a
   macro definition). Rescope "object-bearing" to mean actual object instances
   — an `OBJECT-TYPE` assignment or a notification; bare OID assignments and
   `OBJECT-IDENTITY` registry entries do not count. This also correctly clears
   the v0.5.2 baseline's one module-level finding on `JUNIPER-EXPERIMENT-MIB`
   (verified: it is Juniper's OID registry — `OBJECT-IDENTITY` assignments
   only). Corpus end state: zero module-level `missing-description` findings.
   Covered by `test_oid_assignment_only_module_no_module_level_finding`.

## 4. Watch — #38, #40, C2

1. In `trishul_smi/watch.py`, retain reverse edges for failed modules using each
   `CompileResult.missing_dependencies`. When a newly adopted file supplies
   a missing dependency, recompile the failed module and its dependents in the
   next debounced cycle. Test recovery without editing the dependent (#38).
2. Store the actual local path that supplied each module; do not reconstruct
   it from the declared name. Editing a misnamed source must recompile it and
   its dependents (C2).
3. On deletion, invalidate the removed module and dependents. Prevent the
   offline cache fallback from silently treating that confirmed local deletion
   as a successful watch compile. Try any remaining reader; if none supplies
   the module, mark affected output stale and print its path. Do not delete
   existing output files. Test deletion and later restoration (#38).
4. Track each watched module's latest result. On normal stop, exit 1 if any
   module is still failed, missing, or stale; clear that state after a successful
   recovery. Otherwise exit 0. Test the CLI exit code and update `docs/cli.md`
   (#40).
